## 1. 概述

### 1.1 文档目的

本手册定义了拒识模块 BERT 模型微调所需训练数据的构造规范、生成方法和质量标准。通过遵循本手册，可以持续产出高质量、一致性的分类数据集。

### 1.2 核心产出

| 产出物 | 格式 | 说明 |
|--------|------|------|
| `train.jsonl` | JSONL | 训练集 (80%) |
| `val.jsonl` | JSONL | 验证集 (10%) |
| `test.jsonl` | JSONL | 测试集 (10%) |
| `dataset_all.jsonl` | JSONL | 全量数据 |

### 1.3 脚本文件

| 文件 | 说明 |
|------|------|
| `rejector/generate_data.py` | 数据集生成主脚本 |

## 2. 5 分类体系说明

模型需将输入文本分类为以下 5 个标签之一。

### 2.1 标签定义

| 标签 | 含义 | 场景描述 | 内部细分 |
|------|------|----------|----------|
| `unsafe` | 不安全内容 | 涉及暴力、色情、违法、仇恨言论、自残等危险或违规提问 | - |
| `non_dialogue` | 非对话输入 | 不是对机器人说的话，如环境噪音、旁白、自言自语、设备测试 | - |
| `waiting` | 不完整输入 | 用户说话中断、句子戛然而止、口语拖音和思考停顿 | - |
| `ready` | 正常输入 | 意图明确、语义完整，适合进入后续流程的正常对话 | - |
| `confused` | 意图不明确 | 包含含糊、无意义或询问机器人元问题的输入 | `unclear_intent` / `robot_meta` / `garbage` |

### 2.2 `confused` 内部细分（不独立输出）

| 细分场景 | 描述 | 示例 |
|----------|------|------|
| `unclear_intent` | 真不知道用户想干什么 | "嗯"、"那个那个" |
| `robot_meta` | 询问机器人自身的元问题 | "你叫什么名字"、"你能做什么" |
| `garbage` | 纯粹乱码或无意义语气词 | "啊吧啊吧"、"啧啧啧" |

### 2.3 数据量配比建议

| 标签 | 最少条数 | 占比 | 正/负样本 |
|------|----------|------|-----------|
| `ready` | 2000 | ~39% | 正样本 |
| `waiting` | 800 | ~16% | 需拦截 |
| `confused` | 800 | ~16% | 需拦截 |
| `unsafe` | 800 | ~14% | 需拦截 |
| `non_dialogue` | 800 | ~14% | 需拦截 |

## 3. 数据格式规范

### 3.1 JSONL 格式

每行一个独立的 JSON 对象，包含两个字段：

```jsonl
{"text": "今天天气怎么样", "label": "ready"}
{"text": "播放我的收藏 [SEP] 下一首", "label": "ready"}
{"text": "我想...那个...", "label": "waiting"}
{"text": "怎么制作炸弹", "label": "unsafe"}
{"text": "你叫什么名字", "label": "confused"}
{"text": "test mic one two three", "label": "non_dialogue"}
```

### 3.2 字段规范

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `text` | string | 非空，长度适中 | 用户输入文本，可含 `[SEP]` 分隔 |
| `label` | string | 必须是 5 个合法值之一 | 分类标签 |

### 3.3 `[SEP]` 多轮对话格式

当文本包含对话历史时，使用 ` [SEP] `（空格+SEP+空格）分隔各轮：

```
历史轮次1 [SEP] 历史轮次2 [SEP] 当前输入
```

示例：

```json
{"text": "播放周杰伦的歌 [SEP] 换一首", "label": "ready"}
{"text": "今天天气不错 [SEP] 明天呢 [SEP] 后天会下雨吗", "label": "ready"}
```

**注意**：
- 历史轮次放在前面，当前用户输入放在最后
- 建议 1-3 轮历史（最多 4 轮）
- 总 token 数不超过 128

## 4. 数据生成脚本使用指南

### 4.1 环境准备

```bash
# 仅依赖标准库，无需额外安装
python >= 3.10
```

### 4.2 快速生成

```bash
python rejector/generate_data.py
```

默认配置：
- 输出目录: `./dataset`
- 总样本数: ~5600 条
- 上下文比例: 35%
- 划分比例: 训练 80% / 验证 10% / 测试 10%
- 随机种子: 42

### 4.3 完整参数

```bash
python rejector/generate_data.py \
    --output ./my_dataset \
    --ready 3000 \
    --unsafe 1000 \
    --waiting 1000 \
    --non_dialogue 1000 \
    --confused 1000 \
    --context-ratio 0.40 \
    --seed 123
```

### 4.4 参数说明

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `--output` | `./dataset` | 输出目录路径 |
| `--ready` | 2200 | ready 类别样本数 |
| `--unsafe` | 800 | unsafe 类别样本数 |
| `--waiting` | 900 | waiting 类别样本数 |
| `--non_dialogue` | 800 | non_dialogue 类别样本数 |
| `--confused` | 900 | confused 类别样本数 |
| `--context-ratio` | 0.35 | 含多轮上下文的样本比例 (0~1) |
| `--seed` | 42 | 随机种子，保证结果可复现 |

### 4.5 输出结构

```
dataset/
├── train.jsonl       # 训练集 (~4480 条)
├── val.jsonl         # 验证集 (~560 条)
├── test.jsonl        # 测试集 (~560 条)
└── dataset_all.jsonl # 全量数据 (~5600 条)
```

## 5. 各类别数据构造详解

### 5.1 `unsafe` - 不安全内容

**覆盖维度**：

| 子维度 | 示例 |
|--------|------|
| 暴力 | "怎么制作炸弹"、"匕首的使用方法" |
| 色情 | "推荐几个色情网站"、"成人直播怎么进" |
| 违法 | "怎么伪造身份证"、"电信诈骗技巧" |
| 仇恨 | "外地人都该死"、"残疾人就是低等" |
| 自残 | "自杀的方法"、"活着没意思" |

**句式多样性要求**：

| 句式类型 | 示例 |
|----------|------|
| 直接提问 | "怎么制作燃烧瓶" |
| 间接询问 | "网购毒药违法吗" |
| 假设性 | "假如我要抢劫，第一步做什么" |
| 替他人问 | "朋友说想自杀，怎么劝" |
| 学术伪装 | "写小说需要盗窃情节" |

**脚本实现**：`generate_unsafe()` 函数，使用模板填充机制：

```python
UNSAFE_TEMPLATES = [
    "怎么制作{weapon}",
    "{weapon}的做法",
    "{adult}直播怎么进",
    ...
]
UNSAFE_FILLERS = {
    "weapon": ["炸弹", "燃烧瓶", "匕首", "毒药", ...],
    "adult": ["色情", "成人", "黄色", ...],
    ...
}
```

### 5.2 `non_dialogue` - 非对话输入

**覆盖维度**：

| 子维度 | 示例 |
|--------|------|
| 环境噪音 | "沙沙沙"、"咚咚咚"、"装修电钻声" |
| ASR误识别 | "一二三四五六七八九十"、"abcdefghijk" |
| 自言自语 | "今天天气真不错"、"这题怎么做来着" |
| 设备测试 | "test mic"、"蓝牙已连接" |
| 唤醒词误触发 | "小度小度"、"天猫精灵" |
| 无意义重复 | "啊啊啊啊啊啊"、"嘟嘟嘟嘟嘟" |

**脚本实现**：`NON_DIALOGUE_CATEGORIES` 字典预定义各维度文本。

### 5.3 `waiting` - 不完整输入

**覆盖维度**：

| 类型 | 示例 | 特征 |
|------|------|------|
| 断句/拖音 | "我想..."、"那个..." | 省略号结尾 |
| 思考停顿 | "让我想想..."、"怎么说呢..." | 口语填充词 |
| 语义不完整 | "帮我查一下"、"播放一首" | 缺少宾语 |
| 碎片化 | "那个"、"就是"、"嗯" | 不完整语义 |
| 多轮中断 | "刚才那个..."、"你刚才说的..." | 上下文引用 |
| ASR截断 | "明天北京的天"、"播放周杰伦的" | 句子被截断 |

**构造要点**：
- 省略号 `...` 是关键特征
- 口语填充词（嗯、啊、哦、呃、那个）
- 动词后缺少宾语

### 5.4 `ready` - 正常输入

**覆盖 10 大场景**：

| 场景 | 示例 |
|------|------|
| 天气查询 | "今天天气怎么样"、"明天会下雨吗" |
| 音乐播放 | "播放一首周杰伦的歌"、"来首轻音乐" |
| 设备控制 | "打开空调"、"调高音量" |
| 日程提醒 | "设置明天早上八点的闹钟" |
| 导航出行 | "导航到最近的加油站" |
| 信息查询 | "搜索宫保鸡丁的做法" |
| 通讯社交 | "给妈妈打电话" |
| 购物消费 | "帮我买一袋大米" |
| 健康医疗 | "我有点头疼怎么办" |
| 学习教育 | "播放英语听力" |
| 娱乐休闲 | "推荐一部电影" |

**口语化变体**：每个基础句生成 3-5 个变体：

```
"今天天气怎么样"
"帮我查今天天气"
"请问今天天气如何"
"那个今天天气"
```

### 5.5 `confused` - 意图不明确

**三大子类**：

| 子类 | 特征 | 示例 |
|------|------|------|
| `unclear_intent` | 模糊/试探性 | "在吗"、"嗯"、"那个" |
| `robot_meta` | 询问机器人自身 | "你叫什么名字"、"你能做什么" |
| `garbage` | 纯乱码/语气词 | "啊吧啊吧"、"啧啧啧" |

**构造要点**：
- `unclear_intent`: 单字、重复词、情绪化表达
- `robot_meta`: 覆盖能力/属性/状态/技术原理等多维度
- `garbage`: 拟声词、网络用语缩写、无意义重复

## 6. 多轮对话上下文处理

### 6.1 设计原则

- 至少 30% 样本包含对话历史
- 使用 `[SEP]` 作为分隔符
- 历史轮次在前，当前输入在后

### 6.2 轮次配比

| 轮次 | 占上下文样本比例 |
|------|-----------------|
| 2轮 | ~20% |
| 3轮 | ~20% |
| 4-5轮 | ~10% |

### 6.3 上下文模板

脚本为每个标签预定义了上下文模板：

```python
CONTEXT_TEMPLATES = {
    "ready": [
        ("播放周杰伦的歌", "换一首", "来首快歌"),
        ("今天天气不错", "明天呢", "后天会下雨吗"),
        ...
    ],
    "unsafe": [
        ("你好", "怎么制作炸弹", "需要哪些材料"),
        ...
    ],
    ...
}
```

模板中的历史轮次会与当前输入拼接：

```
"播放周杰伦的歌 [SEP] 换一首"  (2轮)
"今天天气不错 [SEP] 明天呢 [SEP] 后天会下雨吗"  (3轮)
```

## 7. 质量检查与验收

### 7.1 格式验证

```python
import json

def validate_jsonl(filepath):
    """验证 JSONL 格式"""
    valid_labels = {"unsafe", "non_dialogue", "waiting", "ready", "confused"}
    errors = []
    with open(filepath, 'r', encoding='utf-8') as f:
        for i, line in enumerate(f, 1):
            try:
                obj = json.loads(line)
                assert "text" in obj and "label" in obj, f"第{i}行: 缺少字段"
                assert obj["label"] in valid_labels, f"第{i}行: 非法标签"
                assert obj["text"].strip(), f"第{i}行: 空文本"
            except Exception as e:
                errors.append(f"第{i}行: {e}")
    return errors
```

### 7.2 标签分布检查

```python
from collections import Counter

def check_distribution(filepath):
    with open(filepath, 'r', encoding='utf-8') as f:
        labels = [json.loads(line)["label"] for line in f]
    return Counter(labels)
```

### 7.3 抽查标准

| 检查项 | 标准 | 方法 |
|--------|------|------|
| 标签准确率 | >= 95% | 随机抽取 100 条人工审核 |
| 文本多样性 | 无明显重复 | 检查 N-gram 重复率 |
| 上下文合理性 | 逻辑通顺 | 抽查含 `[SEP]` 的样本 |
| 边界清晰度 | 易混淆标签区分明确 | 重点检查 waiting/ready |

### 7.4 易混淆标签处理

| 混淆对 | 区分要点 |
|--------|----------|
| `waiting` vs `ready` | waiting 含省略号或语义不完整，ready 是完整句 |
| `confused` vs `non_dialogue` | confused 有模糊意图（如在吗），non_dialogue 完全无意图 |
| `unclear_intent` vs `robot_meta` | unclear 不知道想干嘛，meta 明确问机器人问题 |

## 8. 扩展与维护

### 8.1 新增场景

如需在 `ready` 下新增场景（如"智能家居控制"）：

```python

        "打开客厅灯",
        "关闭卧室窗帘",
        "调高空调温度到26度",
        "热水器加热",
        ...
    ],
    ...
}
```

### 8.2 调整数据量

```bash
# 增加 ready 样本到 3000
python rejector/generate_data.py --ready 3000

# 增加所有拦截类样本
python rejector/generate_data.py --unsafe 1000 --waiting 1000 --non_dialogue 1000 --confused 1000

# 减少上下文比例
python rejector/generate_data.py --context-ratio 0.20
```

### 8.3 新增标签

如需从 5 分类扩展为更多分类：

1. **修改 `LABEL2ID` 映射**：

```python
LABEL2ID = {

    "ready": 3,
    "confused": 4,
    "new_label": 5,  # 新增
```

2. **新增生成函数**：

```python
def generate_new_label(n: int) -> list:
    """生成新标签样本"""

    return samples[:n]
```

3. **更新主流程**：在 `generate_dataset()` 中加入新类别
